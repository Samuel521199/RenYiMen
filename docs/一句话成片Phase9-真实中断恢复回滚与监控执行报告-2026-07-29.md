## 结论

此前缺少的三类生产证据均已补齐：

1. 在 provider 已提交、Worker 正在轮询时真实杀死 Worker，原 durable job 恢复并完成。

3. 实际暂停新 Worker、切回上一版源码快照、恢复同一个版本锁定任务，并重新部署当前版本。

生产指标仪表盘已加入固定生产栈，由父进程统一启动和停止，不再依赖临时命令。

## 3. 上一版 Worker 实际回滚演练

演练没有使用 legacy fallback，也没有发起付费 provider 请求。

### 3.1 冻结上一版

上一版源码及运行配置被冻结为可执行快照：

```text
.codex-tmp/releases/video-production-v2-bc5888d781eabe7b
runtimeVersion: video-production-v2:bc5888d781eabe7b
```

在停止所有生产 Worker 后创建版本锁定任务：

```text
jobId: cms50jbwl0001tvbwcc39u6v1
kind: image_quality
requiredWorkerVersion: video-production-v2:bc5888d781eabe7b
status: queued
attempt: 0
```

### 3.2 部署新版本并验证拒绝误领

部署新版本 Worker：

```text
runtimeVersion: video-production-v2:04118a638fa8acc8
```

新 Worker 心跳正常，但任务保持：

```text
status: queued
attempt: 0
errorCode: NO_COMPATIBLE_WORKER
recoveryAction: DEPLOY_COMPATIBLE_WORKER
```

这证明新版本没有静默执行上一版 payload。

### 3.3 回滚上一版并恢复

停止新版本栈后，从上一版源码快照启动：

```text
workerId: rollback-previous-quality
runtimeVersion: video-production-v2:bc5888d781eabe7b
supportedKinds: image_quality
```

同一任务完成：

```text
jobId: cms50jbwl0001tvbwcc39u6v1
status: completed
attempt: 1
completedAt: 2026-07-28T18:55:04.628Z
```

随后停止回滚 Worker，并重新启动当前固定生产栈。

## 4. 可持续生产指标仪表盘

入口：

```text
http://127.0.0.1:3011
http://127.0.0.1:3011/metrics
```

仪表盘每 5 秒读取一次数据库投影，保留最近 720 个进程内快照。它现在由
`scripts/start-video-production-stack.mjs` 启动，因此执行：

```text
npm run start:video-production
```

会同时启动固定 Web、四个 Worker 和指标仪表盘；任一关键子进程异常退出时，父进程会终止整组进程，避免半套服务继续运行。
