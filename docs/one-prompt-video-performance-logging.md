# 一句话成片全链路耗时日志

日常排查请直接查看中文日志：

- Windows：`D:\zzz\v debug\一句话成片-耗时日志.log`
- Linux/macOS：`/tmp/one-prompt-video-debug/一句话成片-耗时日志.log`
- 可通过 `ONE_PROMPT_VIDEO_LOG_DIR` 修改目录。

项目内的 `耗时日志.log` 是给制作人员看的“生产账本”，每一行按以下层级显示：

- 北京时间。
- 人类可理解的功能模块，例如“一致性资产规划”“脚本拆解”“关键帧图片生成”。
- 当前原子对象，例如资产名称、视角、第几张候选图和第几轮。
- 原子步骤，例如“编写提示词”“等待大模型返回”“程序质检”“视觉大模型质检”“返修重提”。
- 人类可读的耗时，例如 `825 毫秒`、`23.6 秒`、`2 分 18.4 秒`。
- 执行者是程序、程序硬检查、文本大模型、视觉大模型、图片模型还是视频模型。
- 质检结果、返修方式、模型名称和错误原因等必要上下文。

示例：

```text
[2026-07-27 10:12:01] | 【模块：一致性资产规划】 | 【项目 xxx】 | 【完成】编写故事架构和一致性资产规划提示词 | 耗时 18 毫秒 | 执行者 程序
[2026-07-27 10:12:32] | 【模块：一致性资产规划质检与返修】 | 【项目 xxx】 | 【完成】把提示词交给大模型并等待完整返回 | 耗时 30.7 秒 | 执行者 大模型
[2026-07-27 10:15:44] | 【模块：关键帧图片生成】 | 【对象：关键帧 2 · 候选图 3/4（第 2 轮）】 | 【完成】图片生成模型完成候选图 | 耗时 1 分 42.3 秒 | 执行者 图片生成模型
[2026-07-27 10:15:58] | 【模块：关键帧图片质检】 | 【对象：关键帧 2 · 候选图 3/4（第 2 轮）】 | 【完成】视觉大模型检查候选图 | 耗时 12.6 秒 | 执行者 视觉大模型 | 质检 打回
[2026-07-27 10:16:03] | 【模块：关键帧图片生成】 | 【对象：关键帧 2 · 候选图 4/4（第 3 轮）】 | 【完成】质检打回后等待返修任务重新提交 | 耗时 4.8 秒 | 返修方式 带问题说明重新生成
```

生成任务按原子对象持续携带同一标签，包括资产类别和名称、视角、候选编号、
生成轮次、关键帧编号、片段编号、子分镜编号。该标签会贯穿参考图选择、Prompt
编译、任务提交、模型实际生成、项目存储、质量检查、返修和采用。

脚本拆解会区分参考图事实提取、故事架构与资产设计、故事板设计、逐段镜头拆解、
逐段 Prompt 细化、故事因果修复、镜头拆分修复及重试轮次。

每个项目还有单独文件：

```text
<日志目录>\projects\<projectId>\耗时日志.log
```

程序统计所需的完整原始 JSON 数据继续保存在 `one-prompt-video.log`。项目同步、
前端轮询和上游状态轮询等高频技术流水只保留在 JSON 日志；除非它们失败或单次
超过 10 秒，否则不再写入人类日志，避免淹没真正的生产步骤。

浏览器还会记录 `frontend.api.request.completed`，其中：

- `durationMs`：用户实际等待的完整 API 时间。
- `responseWaitMs`：等待服务端响应头的时间。
- `bodyReadMs`：读取响应体的时间。
- `jsonParseMs`：解析响应和前端收尾时间。
- `traceId`：单次浏览器请求标识。

## 找出慢点

汇总完整日志（输出为中文表格）：

```powershell
npm run analyze:one-prompt-video-log
```

指定日志和项目：

```powershell
npm run analyze:one-prompt-video-log -- "D:\zzz\v debug\one-prompt-video.log" <projectId>
```

项目过滤会自动沿 `taskId`、`jobId`、`candidateId` 等关联标识补齐没有直接携带
`projectId` 的上游事件。结果按累计耗时排序，同时给出次数、平均值、P50、P95
和最大值。

排查时优先比较：

1. `frontend.api.request.completed` 与同时间的 `project.sync.done`：差值大通常是
   鉴权、序列化、网络或浏览器侧等待。
2. `aliyun.storyboard.*.response`：剧本规划各模型阶段。
3. `dashscope.task.submit.response` 与后续查询事件：任务提交和上游生成。
4. `generation_quality.*`：图片/视频质量评估与重试。
5. `compose.local.*`：下载片段、FFprobe、FFmpeg、字幕/音频和 OSS 上传。

日志会清理密钥、Token 和签名字段；仍建议只在受控环境保存，因为项目 ID、
媒体 URL 和生成元数据可用于排障。
