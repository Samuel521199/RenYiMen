## 已完成内容

### 1. 拆除万能恢复分发器

新增并接入以下明确命令：

```text
POST /approve-assets
POST /approve-keyframes
POST /approve-micro-shots
POST /approve-clips
POST /retry-job
POST /repair-contract
POST /continue-task-graph
POST /compose
```

- 删除服务层 `resumeVideoProject()` 万能启发式实现。
- `/resume` 仅保留旧客户端兼容，调用方必须明确提供 `action`。
- 兼容 action 只允许 `CONTINUE_TASK_GRAPH`、`RETRY_JOB`、`REPAIR_CONTRACT`。
- 缺少或无法识别 action 时返回 `EXPLICIT_RESUME_ACTION_REQUIRED`。
- 删除旧 `/approve-images` 路由，统一为 `/approve-keyframes`。
- 片段审批与最终合成分离，审批 clips 不再隐式启动 compose。
- 恢复失败 job 时重排原 job ID，不创建替代 job。

### 2. 统一结构化错误合同

新增统一错误结构：

```json
{
  "errorCode": "...",
  "category": "...",
  "retryable": false,
  "targetId": "...",
  "artifactId": "...",
  "recoveryAction": "...",
  "displayMessage": {
    "zh": "...",
    "en": "..."
  }
}
```

- 命令 API 统一通过同一个响应构造器输出错误。
- `error` 字段仅在兼容期保留作展示，不参与业务判断。
- 前端恢复行为只读取 `taskGraph.allowedActions`、`productionProjection.recoveryAction` 与 `failedJobId`。
- 删除前端通过中英文错误文本匹配来选择恢复动作的逻辑。
- 生产投影现在直接返回失败 job、target、artifact、恢复动作及双语展示信息。

### 3. 自动终态归并

终态 job 失败时，在同一个 Prisma 事务中完成：

1. 释放或失败化 provider lease。
2. 写入 job 的 `errorCode`、`errorCategory`、`recoveryAction`。
3. 更新 artifact metadata 与活动 candidate。
4. 更新对应 keyframe/segment target 投影。
5. 将项目归并到 `WAITING_RECOVERY`。

重试预算耗尽与容量等待超限都会进入该终态归并，不再只修改 job 而让项目继续显示 generating。

### 4. 迁移冻结保护

所有 Phase 7 命令以及计划审批、项目完成确认都复用统一迁移锁检查。冻结期间直接调用 API 会返回：

```text
ONE_PROMPT_MIGRATION_FROZEN
recoveryAction=WAIT_FOR_MIGRATION
HTTP 503
```

## Phase 7 门禁结论

- 同一个按钮只会发出一个确定命令。
- 修改错误展示文本不会改变恢复行为。
- 失败 job 会原子释放容量并重建 target/project 投影。
- 没有 active job 的失败项目不会继续假装处于生成中。
- 旧 `/resume` 无法在未指定 action 时自行审批、重试、规划或合成。
