# 程序优先修复与完整重校验

> 适用合同：`planning-route-v1`  
> 程序实现：`src/services/video-orchestrator/planning-route-deterministic-repair.ts`  
> 接入位置：模型 JSON 首次解析成功后、Route Gate 业务校验之前。

## 1. 原则

程序只修复不需要重新理解用户意图、结果唯一且可审计的简单错误。任何存在两种以上合理答案的情况都不得猜测。

修复流程固定为：

```text
模型原始文本
  → 首次 JSON 解析
  → 简单错误白名单修复
  → 生成逐字段修复审计
  → 重新序列化为 JSON
  → 再次 JSON 解析
  → 从第 1 项开始执行完整 Route Gate
  → allow / warning / deterministic_repair / model_repair / fallback
```

“修复成功”不等于“合同合法”。修复后的结果必须重新经过版本、必填字段、枚举、映射、时间顺序与 Hook、置信度、fallback、事件 ID 和越权字段的全部校验。

## 2. 可程序修复问题白名单

| 规则码 | 问题 | 程序动作 | 安全边界 |
|---|---|---|---|
| `PLANNING_ROUTE_REPAIR_FIELD_ALIAS` | 合法字段使用 snake_case | 改为合同规定的 camelCase | 别名与正式字段值冲突时禁止覆盖 |
| `PLANNING_ROUTE_REPAIR_ENUM_CASE` | 枚举大小写、空格或连字符不规范 | trim、转小写、分隔符转 `_` | 只做形式归一化，不创造新枚举 |
| `PLANNING_ROUTE_REPAIR_UNKNOWN_FIELD_REMOVED` | 顶层或 evidence 中出现合同外字段 | 删除并记录完整 JSON path 和旧值 | 允许字段中的可疑文本不删除，交 Gate 判断 |
| `PLANNING_ROUTE_REPAIR_DEFAULT_CHRONOLOGY` | 缺少 `chronologyMode` | 补 `chronological` | 只处理“缺少”，非法非空值不按缺少处理 |
| `PLANNING_ROUTE_REPAIR_UNIQUE_TEMPLATE` | category 合法、template 缺少且映射唯一 | 补唯一合法模板 | `game` 有两个模板，不自动选择 |
| `PLANNING_ROUTE_REPAIR_DEFAULT_HOOK_POLICY` | `chronological` 缺少 Hook policy 字段 | 仅补缺失项：`curiosity`、`partial`、`false` | 已存在但冲突的值交完整 Gate 修复 |
| `PLANNING_ROUTE_REPAIR_CONFIDENCE_CLAMPED` | 有限数字超出 `0..1` | clamp 到 `0..1` | 字符串、NaN、Infinity 不转换 |
| `PLANNING_ROUTE_REPAIR_AMBIGUITY_NORMALIZED` | ambiguity 缺少、null、空项、重复项或格式不统一 | 归一化为去重数组；缺少/null 变 `[]` | 未知的非空 code 保留给 Gate 判定 |

合法顶层字段别名包括：

```text
video_category              → videoCategory
template_id                 → templateId
chronology_mode             → chronologyMode
hook_mode                   → hookMode
hook_reveal_level           → hookRevealLevel
requires_return_point       → requiresReturnPoint
category_reason             → categoryReason
template_reason             → templateReason
chronology_reason           → chronologyReason
category_confidence         → categoryConfidence
template_confidence         → templateConfidence
chronology_confidence       → chronologyConfidence
ambiguity_codes             → ambiguityCodes
fallback_used               → fallbackUsed
fallback_reason             → fallbackReason
model_name                  → modelName
input_fingerprint           → inputFingerprint
reference_fact_fingerprint  → referenceFactFingerprint
```

`evidence[]` 只接受：

```text
source_type          → sourceType
source_field         → sourceField
reference_fact_field → referenceFactField
summary              → summary
```

## 3. 明确不在白名单内的情况

以下问题不得由简单修复器猜测：

- camelCase 与 snake_case 同时存在但值不同；
- `videoCategory` 缺失或非法；
- `game` 缺少 `templateId`；
- reason 缺失、为空或类型错误；
- evidence 缺失、为空或类型错误；
- confidence 是字符串、NaN 或 Infinity；
- 枚举归一化后仍不是合法枚举；
- 允许文本中夹带剧情、事件 ID 或制作指令；
- 需要理解用户创意才能决定的 category、template、chronology 或 Hook。

字段别名冲突使用 `PLANNING_ROUTE_REPAIR_ALIAS_CONFLICT`，不覆盖任何正式字段，并进入 `model_repair`；没有模型修复机会时进入安全 `fallback`。

## 4. 修复前后审计记录格式

每个字段动作单独记录，不把多个修复合并成一条：

```json
{
  "ruleCode": "PLANNING_ROUTE_REPAIR_FIELD_ALIAS",
  "sourcePath": "$.video_category",
  "targetPath": "$.videoCategory",
  "action": "rename_field",
  "before": {
    "alias": "PRODUCT",
    "canonical": null
  },
  "after": "PRODUCT"
}
```

其他 `action` 合法值：

```text
normalize_enum
remove_unknown_field
apply_default
clamp_number
normalize_array
```

Route Gate 对外返回的 `repairs[]` 保留：

- `ruleCode`
- `sourcePath`
- `path`（目标路径）
- `action`
- `previousValue`
- `repairedValue`

删除字段时 `repairedValue` 为 `undefined`；写入 JSON 日志时应显式转换为 `null` 或增加 `removed: true`，避免序列化后字段消失。

## 5. 修复后重新校验规则

1. 简单修复完成后，必须 `JSON.stringify`。
2. 必须再次解析为单一 JSON object；失败即 `model_repair` 或安全 `fallback`。
3. 必须从 `json_parse` 开始执行 `PLANNING_ROUTE_GATE_VALIDATION_ORDER` 的全部 10 项。
4. 不得因为产生了 `repairs[]` 而跳过必填、枚举、映射或越权校验。
5. 同一次重校验中发现的确定性问题可以继续由 Gate 修复，并追加审计。
6. 重校验后仍需理解意图的问题进入唯一一次 `model_repair`。
7. 模型修复结果再次走相同的“解析—简单修复—完整 Gate”流程。
8. 模型修复机会耗尽后仍不合法，使用程序安全 fallback。
9. 简单修复必须幂等：对修复结果再次运行，应得到相同对象且新增修复记录为 0。

## 6. 典型结果

| 输入问题 | 结果 |
|---|---|
| `video_category: " PRODUCT "`，product 模板缺失 | 归一化为 `product`，自动补 `product_problem_solution`，完整 Gate 通过 |
| `videoCategory: "game"`，模板缺失 | 不猜模板，进入 `model_repair` |
| `categoryConfidence: 1.4` | 修为 `1`，完整 Gate 重新校验 |
| `chronologyMode` 缺失且 Hook policy 缺失 | 补 `chronological + curiosity + partial + false` |
| `videoCategory` 与 `video_category` 值冲突 | 不覆盖，进入 `model_repair` |
| 夹带 `hookEventIds` 或 `cameraGraph` | 删除并保留原路径审计，随后完整 Gate 重校验 |

## 7. 验证

专项测试覆盖：

- 所有白名单修复；
- 唯一映射与 `game` 非唯一映射边界；
- 字段别名冲突；
- 修复审计字段；
- 修复器幂等性；
- 修复后完整 Gate；
- 模型修复与安全 fallback。

npm run test:planning-route
