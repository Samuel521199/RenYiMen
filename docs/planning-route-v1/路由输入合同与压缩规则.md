# 路由输入合同与压缩规则

> 输入合同版本：`planning-route-v1-input`  
> JSON Schema：[planning-route-v1-input.schema.json](planning-route-v1-input.schema.json)  
> 程序实现：`src/services/video-orchestrator/planning-route-input-contract.ts`

## 1. 目标

Route Classifier 只接收完成品类、模板、时间顺序和 Hook policy 判断所需的信息。应用必须先通过 `buildPlanningRouteInput` 构造白名单对象，再序列化给路由模型。禁止直接把项目 Plan、manifest 或参考图长分析拼接进 Prompt。

## 2. 路由输入合同

最终发送给模型的顶层字段固定为：

| 字段 | 必填 | 类型 | 来源 |
|---|---|---|---|
| `version` | 是 | string | 程序注入，固定 `planning-route-v1-input` |
| `userCreative` | 是 | string | 用户创意原文 |
| `durationSeconds` | 是 | number/null | 用户要求的总时长 |
| `aspectRatio` | 是 | string/null | 用户要求的画幅 |
| `stylePreset` | 是 | string/null | 已选择的风格预设名称 |
| `hasReferenceImage` | 是 | boolean | 是否存在参考图；不传图片 URL 或内容 |
| `referenceFacts` | 是 | object | 参考图精简客观事实 |
| `userConstraints` | 是 | string[] | 用户明确限制；无内容时为 `[]` |
| `allowedValues` | 是 | object | 程序注入的合法 category/template/chronology/Hook 枚举 |
| `categoryTemplateMap` | 是 | object | 程序注入的合法分类映射 |

所有字段显式出现，所有对象使用 `additionalProperties:false`。调用方只提供前七个业务字段；`version`、`allowedValues` 和 `categoryTemplateMap` 由程序注入，调用方和模型无权覆盖。

## 3. 输入字符预算

字符数口径为 `JSON.stringify(routeInput).length`。

| 范围 | 硬上限 |
|---|---:|
| 完整路由输入 | 10,000 字符 |
| `userCreative` | 4,000 字符 |
| `stylePreset` | 120 字符 |
| `userConstraints` 数量 | 12 条 |
| 单条用户限制 | 300 字符 |
| 用户限制合计 | 2,000 字符 |
| `referenceFacts` 序列化后 | 800 字符 |

处理原则：

- 不静默截断用户创意；
- 字段或总量超限时返回稳定错误码；
- 不得为了满足预算删除否定词、数字、品牌约束或用户明确限制；
- 程序注入的枚举和映射也计入总字符数。

错误码：

| 错误码 | 含义 |
|---|---|
| `PLANNING_ROUTE_INPUT_UNKNOWN_FIELD` | 顶层出现白名单以外字段 |
| `PLANNING_ROUTE_INPUT_FORBIDDEN_FIELD` | 任意层级出现明确禁止字段 |
| `PLANNING_ROUTE_INPUT_INVALID_FIELD` | 字段类型或值非法 |
| `PLANNING_ROUTE_INPUT_FIELD_BUDGET_EXCEEDED` | 单字段、数组数量或字段合计超限 |
| `PLANNING_ROUTE_INPUT_TOTAL_BUDGET_EXCEEDED` | 完整序列化输入超过 10,000 字符 |

## 4. 参考事实压缩规则

参考图事实最终只保留六个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `subjectTypes` | enum[] | 主体类型 |
| `categorySignals` | enum[] | 是否具有游戏、产品、食品、车辆等类别信号 |
| `containsUi` | boolean | 是否包含 UI |
| `containsBrandElements` | boolean | 是否包含品牌元素 |
| `containsPeople` | boolean | 是否包含人物 |
| `hasExplicitAdCategorySignals` | boolean | 是否具有明确广告品类特征 |

`subjectTypes` 合法值：

```text
person · game_ui · product · food · vehicle · scene · brand_mark · other
```

`categorySignals` 合法值：

```text
game · product · food · auto · ecommerce · brand · tutorial · unknown
```

压缩行为：

1. 只复制合法枚举和严格 boolean；
2. 去重，保持首次出现顺序；
3. `game_ui`、`brand_mark`、`person` 分别确定性设置对应 boolean；
4. 描述、OCR 全文、构图、镜头、材质、色彩长分析和生成建议全部丢弃；
5. `hasReferenceImage=false` 时强制输出空数组和全部 `false`；
6. 不保留 fact ID，因此 Route 输出的 `evidence.referenceFactField` 只能引用上述六个字段名。

```json
{
  "subjectTypes": ["person", "game_ui"],
  "categorySignals": ["game"],
  "containsUi": true,
  "containsBrandElements": false,
  "containsPeople": true,
  "hasExplicitAdCategorySignals": true
}
```

## 5. 禁止传入字段检查清单

程序对对象键执行递归检查，同时识别 camelCase、snake_case 和其他分隔形式。

### 5.1 资产与参考图长内容

- [ ] `assetLibrary`
- [ ] `assetDescription` / `assetDescriptions`
- [ ] `consistencyManifest`
- [ ] `referenceAnalysis` / `fullReferenceAnalysis`
- [ ] `referenceImages` / `referenceImageUrls`
- [ ] `assetImageContract`
- [ ] `assetImagePrompt` / `imagePrompt`

### 5.2 镜头、时间线与关键帧

- [ ] `cameraGraph`
- [ ] `segments`
- [ ] `timeline` / `timelineBlueprint`
- [ ] `keyframes`
- [ ] `keyframeRequirements`
- [ ] `storyboardBrief`

### 5.3 声音与字幕

- [ ] `audioBible`
- [ ] `audioContract`
- [ ] `soundContract`
- [ ] `subtitlePolicy`
- [ ] `subtitleContract`

### 5.4 Provider 与下游合同

- [ ] `provider`
- [ ] `providerCapabilities`
- [ ] `shotDecomposerContract`
- [ ] `storyBeats`
- [ ] `narrativeEvents`

任一层级命中后立即拒绝，不能只在 Prompt 中提示模型忽略。

## 6. 发送前检查顺序

1. 递归检查禁止字段；
2. 检查顶层来源字段白名单；
3. 校验用户创意、时长、画幅和风格类型；
4. 压缩参考图事实；
5. 去重并校验用户明确限制；
6. 程序注入合法枚举和 category/template 映射；
7. 检查单字段预算和完整序列化字符预算；
8. 通过后才允许发送给 Route Classifier。
