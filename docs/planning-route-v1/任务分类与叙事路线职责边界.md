# 任务分类与叙事路线职责边界

> 合同版本：`planning-route-v1`  
> 适用阶段：Planning Architect 的第①步“任务分类与叙事路线”  
> 规范级别：强制  
> 核心原则：本阶段只决定“后续应该沿哪条叙事路线规划”，不创作路线中的任何具体剧情内容。

## 1. 阶段定位

第①步是一个轻量、独立、可缓存的路由判断器。它读取用户需求、显式项目参数以及已抽取的参考事实，只输出分类、模板、时间模式、Hook 路线和判断可靠性。

它的输出是后续 Planning 阶段的输入约束，不是剧情方案，也不是 Storyboard。

```mermaid
flowchart LR
    I["白名单输入<br/>需求 · 项目参数 · 参考事实"]
    R["第①步 Route Classifier<br/>只做路线判断"]
    C["planning-route-v1<br/>严格结构化合同"]
    P["后续 Planning<br/>事件 · 资产 · Segment · 声音"]

    I --> R --> C --> P
```

## 2. 允许负责

本阶段只允许完成以下八项职责：

1. 判断视频品类 `videoCategory`；
2. 选择叙事模板 `templateId`；
3. 选择时间顺序模式 `chronologyMode`；
4. 决定 Hook 的基本类型 `hookMode`；
5. 决定 Hook 可以透露多少结果 `hookRevealLevel`；
6. 给出分类、模板和时间模式的判断理由；
7. 给出三项判断各自的置信度和歧义代码；
8. 无法可靠判断时执行安全回退，并说明原因。

`requiresReturnPoint` 只能表达“开场预览结果后，后续叙事是否必须返回较早时间点”，不能指定返回到哪个事件。

## 3. 禁止负责

本阶段禁止：

1. 编写具体剧情事件；
2. 生成 Hook、冲突、转折、兑现和 CTA 的详细文案；
3. 生成任何事件 ID；
4. 绑定 `hookEventIds` 等事件引用；
5. 建立人物、产品、场景或道具资产锚点；
6. 分配 Segment、镜头或关键帧；
7. 分配总时长、Segment 时长或节奏预算；
8. 生成声音、音乐、音效、旁白策略；
9. 生成字幕、屏幕文字或本地化策略；
10. 生成资产图片合同；
11. 生成关键帧 Prompt、图片 Prompt 或视频 Prompt；
12. 修复下游 Story Contract、资产合同或时间线错误。

如果模型认为某项下游创作“有助于解释分类”，也不能把它写入输出；只能在 `evidence` 和三个 reason 字段中说明判断依据。

## 4. 输入字段白名单

路由阶段只接受下列精简顶层字段。输入对象及其嵌套对象均执行 `additionalProperties: false`；未列出的字段应在进入模型前被拒绝。

| 字段 | 必填 | 类型 | 用途 | 限制 |
|---|---|---|---|---|
| `version` | 是 | string | 输入合同版本 | 固定为 `planning-route-v1-input` |
| `userCreative` | 是 | string | 用户创意原文 | 不得混入旧 Planning 输出 |
| `durationSeconds` | 是 | number/null | 用户要求的总时长 | 不用于分段 |
| `aspectRatio` | 是 | string/null | 用户要求的画幅 | 例如 `9:16`、`16:9`、`1:1` |
| `stylePreset` | 是 | string/null | 用户选择的风格预设名称 | 只作为弱证据 |
| `hasReferenceImage` | 是 | boolean | 是否有参考图 | 不传图片 URL、base64 或二进制 |
| `referenceFacts` | 是 | object | 六字段精简客观事实 | 不保留长描述和 fact ID |
| `userConstraints` | 是 | string[] | 用户明确限制 | 默认 `[]` |
| `allowedValues` | 是 | object | 合法枚举 | 由程序注入 |
| `categoryTemplateMap` | 是 | object | 分类映射规则 | 由程序注入 |

### 4.1 `referenceFacts` 子字段白名单

只允许 `subjectTypes`、`categorySignals`、`containsUi`、`containsBrandElements`、`containsPeople`、`hasExplicitAdCategorySignals`。详细压缩方法、字符预算和禁止字段检查清单见 [路由输入合同与压缩规则](路由输入合同与压缩规则.md)。

### 4.3 明确不能作为本阶段输入的内容

即使上游已经存在，以下内容也不能进入 Route Classifier 的模型上下文：

- 旧的 `narrativeEvents`、`storyBeats` 或 `creativeStrategy` 详细文案；
- 事件 ID 和事件引用；
- consistency manifest、资产锚点和资产图片合同；
- Segment、timeline blueprint、镜头、关键帧；
- 音频、字幕、图片或视频 Prompt；
- 下游门禁错误及其返修文本。

这样可以避免分类结果被旧剧情或旧错误反向污染，也能让输入大小和 token 成本可独立测量。

## 5. 输出字段白名单

`planning-route-v1` 顶层只能包含以下 20 个字段：

| 分组 | 字段 |
|---|---|
| 分类结果 | `videoCategory`、`templateId`、`chronologyMode` |
| Hook 路线 | `hookMode`、`hookRevealLevel`、`requiresReturnPoint` |
| 判断依据 | `categoryReason`、`templateReason`、`chronologyReason`、`evidence` |
| 可靠性 | `categoryConfidence`、`templateConfidence`、`chronologyConfidence`、`ambiguityCodes`、`fallbackUsed`、`fallbackReason` |
| 合同元数据 | `version`、`modelName`、`inputFingerprint`、`referenceFactFingerprint` |

除 `evidence` 项内部明确列出的字段外，不允许任何额外属性。完整定义见 [planning-route-v1 字段定义](planning-route-v1-字段定义.md)。

## 6. 禁止输出字段清单

以下字段及同义变体一律禁止出现在输出中。

### 6.1 事件及事件引用

- `events`
- `narrativeEvents`
- `storyBeats`
- `eventId`、`eventIds`
- `hookEventIds`
- `conflictEventIds`
- `turningPointEventIds`
- `payoffEventIds`
- `ctaEventIds`
- `returnToEventId`
- `previousEventIds`
- `sourceEventIds`
- `dependsOnEventIds`

原因：分类阶段尚未生成剧情事件，不能引用不存在的 ID。

### 6.2 具体剧情文案

- `hook`、`hookZh`、`hookEn`
- `conflict`、`conflictZh`、`conflictEn`
- `turningPoint`
- `payoff`
- `cta`
- `logline`
- `story`
- `script`
- `conversionCopy`

允许输出 `hookMode` 和 `hookRevealLevel`，但不允许输出 Hook 句子。

### 6.3 资产与一致性

- `consistencyManifest`
- `anchors`
- `anchorId`、`anchorIds`
- `characters`
- `products`
- `locations`
- `props`
- `assetImageContract`
- `assetDependencies`
- `anchorStateTimeline`

### 6.4 时间线与镜头

- `segments`
- `segmentCount`
- `segmentNo`
- `segmentDuration`
- `timelineBlueprint`
- `durationAllocation`
- `shots`
- `shotGroupingPass`
- `keyframes`
- `cameraGraph`
- `transitionPlan`

输入可以包含用户要求的总时长 `durationSeconds`，输出不能进行任何时长分配。

### 6.5 声音、字幕与生成 Prompt

- `audioBible`
- `soundStrategy`
- `musicStrategy`
- `voiceover`
- `sfx`
- `subtitlePolicy`
- `subtitles`
- `onScreenText`
- `imagePrompt`
- `keyframePrompt`
- `videoPrompt`
- `negativePrompt`

## 7. 阶段通过条件

只有同时满足以下条件，路由阶段才算通过：

1. 输出能通过 `planning-route-v1.schema.json`；
2. 只有白名单字段，没有任何额外字段；
3. `videoCategory` 与 `templateId` 是合法组合；
4. `chronologyMode`、Hook 路线和 `requiresReturnPoint` 互相一致；
5. 三个 reason 均说明依据，不包含具体剧情创作；
6. 三个 confidence 均为 `0..1`；
7. 不确定时 `fallbackUsed=true`，并同时提供歧义代码和回退理由；
8. 两个 fingerprint 能对应本次规范化输入；
9. 不含任何事件、资产、Segment、时长分配、声音、字幕或生成 Prompt。

不通过时只允许重新执行路由分类或走确定性安全回退，不得在本阶段启动剧情合同返修。
