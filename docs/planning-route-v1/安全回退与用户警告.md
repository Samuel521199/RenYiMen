# 安全回退与用户警告

> 适用合同：`planning-route-v1`  
> 程序实现：`src/services/video-orchestrator/planning-route-safe-fallback.ts`

## 1. 默认 Fallback

无法可靠确定分类、定向修复失败或修复机会耗尽时，程序生成固定路线：

```json
{
  "videoCategory": "custom",
  "templateId": "generic_brand_story",
  "chronologyMode": "chronological",
  "hookMode": "curiosity",
  "hookRevealLevel": "none",
  "requiresReturnPoint": false,
  "fallbackUsed": true
}
```

同时：

- 三项 confidence 固定为 `0`；
- `ambiguityCodes` 至少包含 `INSUFFICIENT_EVIDENCE`；
- 输入存在品类冲突时追加 `CATEGORY_CONFLICT`；
- metadata 使用应用计算值；
- 不复用未通过 Gate 的剧情或制作内容；
- 不提前透露最终结果。

## 2. Fallback 原因模板

`fallbackReason` 必须同时回答三个问题：

```text
为什么无法判断？
→ {主要原因}

哪些输入存在冲突？
→ 冲突信息：{冲突列表；没有明确冲突时写明未发现}

用户下一步可以做什么？
→ 已使用通用品牌故事顺叙路线继续规划，
  建议在计划审核阶段确认或修改品类与叙事路线。
```

稳定基础模板：

| 场景 | 原因模板 |
|---|---|
| 证据不足 | `输入证据不足，无法可靠确定视频品类或叙事模板。` |
| 输入冲突 | `用户文本与参考信息存在冲突，无法可靠确定唯一品类。` |
| 模型结果非法 | `路由模型结果未通过合同校验，且没有可用的定向修复结果。` |
| 系统不支持 | `用户要求包含当前系统不支持的内容。` |

`inputConflicts[]` 保存去重后的冲突摘要，最多取前四项写入合同原因，完整结构仍保留在 `fallbackInfo`。

## 3. 用户可见 Warning

普通安全回退使用：

```text
暂时无法可靠判断视频品类，已使用“通用品牌故事 + 顺叙”继续生成计划。
建议在计划审核阶段确认或修改品类、模板和时间顺序。
```

存在输入冲突时，在中间追加：

```text
发现冲突：{最多三项输入冲突}。
```

该文案通过 `fallbackInfo.userVisibleWarning` 提供给调用方。调用方应在计划审核页显示 warning，而不是把内部 Gate 错误直接展示给用户。

## 4. 是否阻断 Planning

默认：

```text
shouldBlockPlanning=false
recommendPlanReview=true
```

因此无法确定分类不会阻断 Planning。系统继续生成通用计划，让用户在计划审核阶段调整。

只有上游明确传入 `unsupportedContentReason` 时：

```text
shouldBlockPlanning=true
recommendPlanReview=false
```

此时不调用 Route 模型，用户提示为：

```text
当前请求包含系统暂不支持的内容，Planning 已停止：{具体原因}
```

程序不会根据模糊关键词自行判定“不支持”。必须由能力检查、内容支持矩阵或明确的上游校验结果提供 `unsupportedContentReason`。

## 5. 结构化审计

`fallbackInfo` 包含：

| 字段 | 含义 |
|---|---|
| `reason` | 主要回退原因 |
| `inputConflicts` | 冲突输入摘要 |
| `recommendPlanReview` | 是否建议在计划审核阶段修改 |
| `shouldBlockPlanning` | 是否必须停止 Planning |
| `blockingReason` | 阻断原因；普通回退为 `null` |
| `userVisibleWarning` | 可直接展示给用户的 warning |

Route Contract 保持原有20字段，不把 UI 状态混入模型合同；`fallbackInfo` 属于 Gate/调用结果的旁路审计信息。
